# MultiFields Kelvinion

Beta，依据 Kelvinion v3.1.1 手册实现，尚未验证实机。首版只支持 USB-B 虚拟串口；
VISA 还支持 GPIB 和 LAN，但本驱动不使用它们。

1. 把整个 `mf_kelvinion/` 复制到 `OpenLabControl/system_instruments/`。
   实机需能在设备管理器或 NI MAX 中看到 USB 串口，并安装 NI-VISA。仪表选串口通讯模式。
2. 在 Instrument Scanner 扫描并选择该 COM 口对应的 `ASRL…::INSTR`。即使扫描器显示
   **no IDN response**，也可手动选择已列出的正确地址。通用扫描用普通 `*IDN?`，
   Kelvinion 后端连接后才用 115200、8N1、无流控和 `[*IDN?]` 确认身份。
3. Controller 的 **Reading** 对应输出 1 (A) 在仪表上已绑定的传感器输入。
   若用作标准温控，将其 **Sequence Role** 设为 **Sample Temp**。
   确认现场上下限和速率；默认 3–300 K、3 K/min、最大 10 K/min。
4. 如需联动，勾选 **Control Output 2 (B)**，选它实际绑定的探头，填写目标公式。
   `x` 是主目标温度（K），例如 `0.8*x+0.5`。仅支持数字、括号和四则运算。
   两路使用同一个升降温速率并共用扫描器里的温度上下限，第二路目标按 0.01 K 舍入。
   对两路分别校验仪表 PID 限值和探头曲线上限。取消勾选只停止程序控制 B，不关闭加热器。

仪表端预设回路、Auto 模式、PID、Zone、输出档位与开关。OpenLab 不主动更改这些设置；
只写速率和目标并逐项读回。仪表不支持两路原子更新；写入结果不明时停止，不重试，
先到仪表面板核对两路状态。SEQ 正常结束、停止或退出应用时不自动改变输出；
手动 **Hold Current** 将参与控制的各路目标设为各自当前温度，不套联动公式。

前面板及状态日志可记录两路目标、速率、加热输出百分比及档位，温度网格显示 A/B。
测量取样只读主温度；SEQ 的稳定判定只针对 Sample Temp，不把第二路当独立的等待条件。
当前按手册第 5 章的读取帧格式实现；首轮实机应核对 `SET` 后固件是否额外发送回执，
以及目标读回是最终设定值还是动态 Ramp 设定值。请先读状态，再用安全条件下的小幅变化测试。
